# Silta RFCs

RFCs are used for significant architectural decisions.

Examples:

- Python/Rust execution boundary.
- Routing architecture.
- ORM model representation.
- Deployment model.
- Plugin system.
- Compatibility guarantees.
- Public API changes.

Small bug fixes do not require RFCs.

An RFC should contain:

1. Problem.
2. Motivation.
3. Proposed solution.
4. Alternatives.
5. Performance implications.
6. Compatibility implications.
7. Open questions.

Accepted RFCs should be implemented incrementally. Rejected or superseded RFCs
should remain in the repository for context.
