# Governance

Silta is an open-source project.

Silta was originally conceived and initiated by Serrka.

The project is initially maintained by the founding maintainers.

As the community grows, maintainership should become increasingly
community-driven.

Technical decisions should be made in public whenever practical.

Major architectural decisions should use RFCs.

Sponsorship supports project development but does not grant control over the
technical roadmap.

## Maintainer Responsibilities

- Code review.
- Releases.
- Security.
- Architecture.
- Roadmap.
- Contributor support.
- Review contributions for architectural fit and implementation quality.
- Keep public claims aligned with working code and measured results.
- Require RFCs for major API, runtime, or dependency decisions.
- Protect the project from unnecessary scope expansion.
- Maintain a respectful, technical contribution environment.

## Decision Process

Small implementation changes can be handled through pull requests. Larger
changes should start as RFCs, especially when they affect the Python API,
runtime boundary, application IR, or dependency commitments.

When consensus is not obvious, maintainers should document the tradeoffs and the
reason for the decision in the relevant issue, pull request, or RFC.
